# 行测知识点树总指导

## 1. 文档定位

本文档不是百科目录，而是 `行测` 知识点树的总指导。

这棵树后面要同时服务 4 件事：

1. 学习路径：用户知道先学什么、后学什么。
2. 内容生产：每个知识点都能写出真正能用的教学内容。
3. 题目标注：每道题能挂到相对稳定的分类上。
4. 复盘统计：能看出薄弱点到底是题型、模型、方法还是易错点。

目标不是把树做得越多越好，而是让用户按照这套体系学习后，具备冲击 `80+` 的可执行路径。

## 3. 行测知识点树的总原则

### 3.1 树是为了提分，不是为了好看

一个知识点能不能留在树里，核心看 3 件事：

1. 能不能稳定识别。
2. 能不能指导解题。
3. 能不能支撑复盘。

如果一个节点只能起到“看起来很专业”的作用，但既不好挂题，也不能指导内容，那就不应该过度细分。

### 3.2 同一层尽量只放一种维度

同级节点必须尽量保持同一分类口径，不能一半是题型，一半是方法，一半又是材料形式。

否则会出现 3 个问题：

1. 用户学习路径混乱。
2. content 写作很难统一结构。
3. 同一道题不知道该挂到哪一层。

### 3.3 高频模块要深，低频模块要稳

对冲击 `80+` 来说，不同模块的树深度不能平均主义。

建议原则：

1. `数量关系 / 判断推理 / 言语理解 / 资料分析` 必须做成主战模块。
2. `常识判断` 要适度细，但不要做成百科全书。
3. `政治理论` 如果保留在 `行测` 下，应保持浅层，不要抢占过多维护成本。

### 3.4 节点要能落到“可解题动作”

真正有价值的叶子节点，不是纯名词，而是能让用户一看到题就知道该怎么动手。

例如好的节点会天然对应：

1. 识别信号
2. 核心公式
3. 标准步骤
4. 常见陷阱
5. 典型例题

这种节点最适合后续写 content，也最适合挂题和复盘。

### 3.5 不追求一次性把所有细节拆到极致

树的建设顺序应该是：

1. 先保证主干正确。
2. 再补高频题型。
3. 最后补特殊变体和易错点。

先有稳定骨架，再向下增量细分，成本最低，也最不容易返工。

## 4. 第一阶段结论

截至 `2026-04-09`，当前后端的最大问题不是“知识点不够多”，而是：

1. `数量关系` 深得太快。
2. 其他四个核心提分模块还没有形成可教学、可挂题、可复盘的完整树。
3. 某些模块内部存在分类维度不统一的问题。

因此，后续补树不应该继续优先往 `数量关系` 无限制下钻，而应该先把整棵 `行测` 主树拉回到结构均衡。

## 5. 下一步建议

下一轮建议只做一件事：

1. 明确六大模块各自应该拆到几级。
2. 给出每个模块的“终局结构模板”。
3. 先确定补树优先级，再开始逐模块落 SQL。

下一轮优先展开顺序建议：

1. 判断推理
2. 言语理解与表达
3. 资料分析
4. 常识判断
5. 政治理论
6. 数量关系结构校准
