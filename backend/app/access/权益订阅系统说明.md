# 题库权益订阅系统说明

> 目标读者:后端 / 全栈同事(非 access 模块作者)
> 解决的问题:**为什么有的题库不要权限,有的题库要权限?权益到底是怎么算出来的?**
> 维护位置:`backend/app/access/`(权益决策核心) + `backend/app/question_bank/service/membership_service.py`(题库侧适配层)

| 激活码兑换会给用户开会员吗? | **目前不会**。`activation_service.py:48` 是 TODO,只扣码不发权益,需要运营手动补订阅 | `backend/app/question_bank/service/activation_service.py:48` |

## 1. 整体架构

```
┌──────────────────────────────────────────────────────────────┐
│  C 端请求 (创建会话 / 取题目 / 收藏 …)                       │
└──────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌──────────────────────────────────────────────────────────────┐
│  question_bank/api/v1/*.py                                   │
│  (调 membership_service.verify_xxx)                          │
└──────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌──────────────────────────────────────────────────────────────┐
│  question_bank/service/membership_service.py  ← 适配层       │
│  把 "bank_id / chapter_id / question_id" 翻译成              │
│  AccessContext, 再喂给决策引擎                                │
└──────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌──────────────────────────────────────────────────────────────┐
│  access/engine/decide.py  AccessDecisionEngine               │
│  ① rule_resolver:查 resource_rule(资源要什么权益?)         │
│  ② snapshot_service:查用户的 subscription + direct_grant   │
│  ③ evaluators 责任链按序投票:                                │
│     FreePass → Ownership → SubscriptionAccess               │
│              → DirectGrant → QuotaTrial                      │
│  ④ 任一 allow 即放行;全 pass 即 deny(NO_MATCHING_GRANT)   │
│  ⑤ deny 时落 decision_log 一行,allow 不落                  │
└──────────────────────────────────────────────────────────────┘
```

**两个模块的职责切分要记住:**

- `backend/app/access/` —— 通用决策引擎,**不知道**自己服务的是题库还是视频。它只认 `(resource_type, resource_id)`。
- `backend/app/question_bank/service/membership_service.py` —— 题库侧的"翻译官",负责把"篇章 → 题库"、"题目 → 所属题库"、"批量题目 → 批量题库"翻译成引擎能吃的输入,并把 deny 翻译成 `ForbiddenError` 抛出。

## 2. 数据模型(全部在 `backend/app/access/model/`)

### 2.1 用户身份(不在 access 模块,要注意)

`backend/app/question_bank/model/user.py:21-71` 的 `UserAccount` 表 **完全不存储会员状态**。是不是会员、是哪一档,**全靠运行时根据 subscription 算出来**。

> ⚠️ **不要在用户表上加 `is_vip` / `vip_level` 字段!** 这与现行设计冲突。要查会员状态,调 `snapshot_service.load(db, user_id)` 拿快照。

### 2.2 权益字典:`entitlement`

`access/model/entitlement.py:24`

| 字段 | 说明 | 例 |
| --- | --- | --- |
| `code` | 业务唯一编码 | `qbank.advanced_filter`、`qbank.knowledge_practice` |
| `category` | 权益类别 | `access` / `quota` / `boost` / `feature` |
| `metric` | 计量单位(配额时用) | `monthly_quota` |
| `verb` | 动作 | `read` / `write` |
| `resource_type` | 资源类型限定 | `qbank` |

权益是**最细粒度的能力凭证**。例如:
- `qbank.advanced_filter` = 能用按年份/地区/分类筛题
- `qbank.knowledge_practice` = 能按知识点刷题
- `qbank.access:<bank_id>` 或类似 = 能访问某个具体题库

### 2.3 权益包:`entitlement_pack` + `pack_item`

`access/model/pack.py:19, 51`

- `entitlement_pack(code, grade, domain_id)` —— 把多个 entitlement 打包成可售卖的单元
- `pack_item(pack_id, entitlement_id, value_int, value_meta)` —— 多对多关系 + 数值(用于配额上限)

`grade` 字段是 `basic/standard/premium/elite` —— 这是包的"档位标签",但业务**不直接按 grade 判定**,而是按"包里有哪些 entitlement code"判定。

### 2.4 售卖模板:`subscription_template` + `template_pack`

`access/model/template.py:23, 66`

| 字段 | 说明 |
| --- | --- |
| `kind` | `standard` / `bundle` / `trial` / `gift` / `corporate` |
| `duration_days` | 一次购买可用多少天 |
| `auto_renewable` | 是否自动续费 |
| `price_cents` | **价格,以分为单位**(整个系统里题库本身不存价格) |
| `sale_period` | 销售时段 |

`template_pack` 把模板与权益包关联 —— 一个模板可以打包多个包。

### 2.5 用户实际持有:`subscription`

`access/model/subscription.py:23`,**这是"用户买了什么"的唯一来源**。

```python
class Subscription(Base):
    user_id: int                                    # 谁
    template_id: int                                # 买的哪个模板
    valid_period: Range[datetime]  # TSTZRANGE      # 什么时间内有效(开区间/闭区间随业务)
    source: str   # order/actcode/quest/gift/admin/migration
    status: str   # active/expired/cancelled/refunded
    parent_subscription_id: int | None              # 续费链路
```

`valid_period` 用的是 **PostgreSQL TSTZRANGE 类型** + GiST 索引,判定有效性时直接 `valid_period @> NOW()`。

### 2.6 运营赠送通道:`direct_grant`

`access/model/grant.py:24`,**不走订阅模板,直接挂在用户头上的权益**。

```python
class DirectGrant(Base):
    user_id: int
    entitlement_code: str            # 直接绑 entitlement code
    valid_period: Range[datetime]
    source: str  # admin/compensation/promo/quest/invite
```

用法:
- 运营补偿(用户投诉处理)
- 任务奖励(连续签到 7 天送 7 天会员)
- 邀请激励
- 活动赠送

### 2.7 ⭐ 资源规则:`resource_rule`(本系统的核心)

`access/model/rule.py:23`

```python
class ResourceRule(Base):
    resource_type: str        # qbank / content / video / live / category
    resource_id: int          # 资源主键
    entitlement_code: str     # 访问这个资源需要哪个 entitlement
    grant_mode: str           # access / trial / free_pass / ownership_required
    priority: int             # 多条规则时的优先级
    valid_period: Range[datetime]  # 规则本身的生效时段(限免活动用)
    audience_filter: dict     # 人群过滤(可选)
    inherit_to_children: bool # 是否继承给子资源
```

**这是回答"为什么这个题库要会员"的唯一权威表**。

`grant_mode` 四个值的含义(`access/constants.py:91-97`):

| grant_mode | 含义 | 评估器位置 |
| --- | --- | --- |
| `access` | 需要订阅或 direct_grant 提供同 code 的权益 | `subscription_access.py`, `direct_grant.py` |
| `trial` | 试看,扣减配额,扣完即拒 | `quota_trial.py` |
| `free_pass` | 限免,放在 valid_period 内对所有人放行 | `free_pass.py` |
| `ownership_required` | 单点买断(占位,**尚未实现**) | `ownership.py` |

### 2.8 题库表上的 `access_entitlement_code` 字段(**陷阱预警**)

`backend/app/question_bank/model/bank.py:76-80`:

```python
access_entitlement_code: Mapped[str | None] = mapped_column(
    sa.String(64), default=None,
    comment='访问所需权益编码,为空表示公开',
)
```

⚠️ **这个字段目前只是声明性标签,运行时鉴权完全不读它。**

- 它**只**在 `bank_service.py:103-126` `_validate_access_entitlement_code` 校验 entitlement 是否存在 / 是否 active 时被读到。
- 决定题库"要不要会员"的真正依据是 `resource_rule` 表(`access/engine/decide.py`)。

所以**改这个字段不会让题库变成付费,加一条 `resource_rule` 才会**。这是一个潜在的不一致点,后续如果要统一,要么把 `bank.access_entitlement_code` 接入引擎,要么干脆删掉这个字段。**改之前要先评估**。

### 2.9 决策日志:`decision_log` & 配额账本:`direct_grant_ledger`

- `access/model/decision.py` —— **只在 deny 时落表**,记录原因码、命中规则、用户快照。allow 不落库,所以不能用来做"访问审计"。
- `access/model/ledger.py` —— 配额扣减流水(`grant_mode=trial` 用)。

## 3. 一道题被刷,会经过哪些校验?

以 **"创建练习会话"** 这个最核心的路径为例(`POST /api/v1/qbank/practice/sessions`):

```
┌─ 入口: backend/app/question_bank/api/v1/session.py:33 create_session
│
├─ 第 1 步:判断是否复习类会话
│  is_review_session = obj.session_type in {'wrong', 'favorite', 'note'}
│  (复习类会话从这里开始,后续 3 个校验全跳过)
│
├─ 第 2 步:题库/篇章解析 + 题库权益校验
│  if obj.chapter_id is not None:
│      → membership_service.resolve_bank_context_for_chapter(...)
│        ├─ 把 chapter_id 反查到 bank_id
│        └─ 若 user_id 非 None,顺带调 verify_bank_access(...)
│           → access_decision_engine.decide(QBANK, bank_id)
│           → 查 resource_rule + 用户 snapshot,5 个 evaluator 表决
│  elif obj.bank_id and not is_review_session:
│      → membership_service.verify_bank_list_access(...)
│        (其实就是 verify_bank_access 的别名)
│
├─ 第 3 步:高级筛选权益(跨域功能,不走资源决策引擎)
│  if not is_review_session:
│      → membership_service.verify_filter_access(...)
│        当传了 cat_id / year_start / year_end / region / 关键字 任一时,
│        要求用户拥有 entitlement code `qbank.advanced_filter`
│
├─ 第 4 步:知识点权益(同上,功能型)
│  if not is_review_session:
│      → membership_service.verify_knowledge_access(...)
│        当传了 knowledge_point / knowledge_ids / knowledge_names 任一时,
│        要求用户拥有 entitlement code `qbank.knowledge_practice`
│
└─ 第 5 步:Service 层兜底校验
   session_service.create_unified_session(...)
   再调一次 resolve_bank_context_for_chapter,
   防止其他入口(比如内部任务)绕过 API 层校验
```

**校验失败时**会抛 `ForbiddenError(403)`,前端拿到的中文 msg 是:

| 校验点 | 失败提示 | 行号 |
| --- | --- | --- |
| 题库权限 | `当前题库需要会员权限` | `membership_service.py:113` |
| 单题权限 | `当前题目需要会员权限` | `membership_service.py:274` |
| 高级筛选 | `当前筛选条件需要会员权限` | `membership_service.py:413` |
| 知识点 | `按知识点刷题需要会员权限` | `membership_service.py:447` |
| 篇章关系不匹配 | `篇章 ID X 不属于题库 ID Y 的篇章来源` | `membership_service.py:154` |
| 不是自己的会话 | `无权访问此会话` | `membership_service.py:465` |

## 4. 复习类会话(错题/收藏/笔记)为什么不要权限?

**核心理念**:权益管的是「**新建数据**的能力」,不是「**已沉淀私有数据**的访问」。

用户在会员有效期内做错的题、收藏的题、写的笔记,已经存到了:

- `WrongQuestion`(错题本)
- `QuestionFavorite`(收藏)
- `QuestionNote`(笔记)

这些都是**用户的私有数据**。会员到期后,这部分数据用户应当继续能复习 —— 因此 `session_type ∈ {'wrong', 'favorite', 'note'}` 时**绕过所有权益校验**。

**绕过点有两处(冗余防御):**

```python
# ① API 层 — backend/app/question_bank/api/v1/session.py:40-70
is_review_session = obj.session_type in {'wrong', 'favorite', 'note'}

if obj.chapter_id is not None:
    obj.bank_id = await membership_service.resolve_bank_context_for_chapter(
        ...,
        user_id=None if is_review_session else request.user.id,  # ← 传 None 跳过 bank 权益校验
    )
elif obj.bank_id and not is_review_session:
    await membership_service.verify_bank_list_access(...)

if not is_review_session:
    await membership_service.verify_filter_access(...)
    await membership_service.verify_knowledge_access(...)

# ② Service 层 — backend/app/question_bank/service/session_service.py:1792-1802
# 同口径再做一遍,防止其他入口绕过 API 层
```

⚠️ **不要把这两处合并成一处**。冗余是有意为之 —— 任何新增的"绕过 API 直接调 Service"的链路(后台任务、迁移脚本)都能受到 Service 层兜底保护。

## 5. 三种特殊场景

### 5.1 限免活动(grant_mode=free_pass)

运营给某题库挂一条 `resource_rule(grant_mode='free_pass', valid_period=[2026-05-01, 2026-05-08))`。

`FreePassEvaluator`(`access/engine/evaluators/free_pass.py:37-49`)对所有用户放行,**不查 subscription**。活动期结束自动失效。

### 5.2 试看(grant_mode=trial)

⚠️ **在题库场景下目前永远不生效**。

`membership_service._decide_resource`(`:42-71`)调引擎时永远写死 `consume_trial=False`,导致 `QuotaTrialEvaluator` 不会扣额度也不会放行。

如果产品要开启试看,需要:
1. 把 `consume_trial` 提到 `_decide_resource` 的入参
2. 在调用方(`verify_bank_access` 等)按场景决定是否消耗配额
3. 设计前端"试看一次提示"的交互

### 5.3 运营赠送(DirectGrant)

`source` 字段标识赠送来源:`admin`(管理员)/`compensation`(补偿)/`promo`(活动)/`quest`(任务)/`invite`(邀请)。

`DirectGrantEvaluator`(`access/engine/evaluators/direct_grant.py`)会扫描用户的所有有效 direct_grant,只要有任一条 `entitlement_code` 与当前规则要求一致就 allow。

## 6. 已知坑 / 需要警惕的地方

### 6.1 题库表 `access_entitlement_code` 字段是死字段

见 §2.8。**改它不影响运行时鉴权**,真要让某题库变付费必须去 `resource_rule` 加规则。

### 6.2 激活码兑换只扣码不发权益

`backend/app/question_bank/service/activation_service.py:48`:

```python
# TODO: 兑换成功后创建会员权益(会员系统后续补充)
```

目前激活码 `redeem` 接口跑成功后:
- ✅ 激活码表 `actcode` 状态会变成 "已使用"
- ✅ `actcode_usage` 会写一条使用流水
- ❌ **`subscription` 不会新增,`direct_grant` 也不会新增**

意味着用户兑换成功了但什么权益都没拿到。需要运营手动补订阅,或后续补完这段 TODO。

### 6.3 `verify_question_ids_access` 与 `verify_question_access` 语义不一致

`backend/app/question_bank/service/membership_service.py`:

- 单题版 `verify_question_access`(`:244-274`):反查题目所属所有题库,**任一题库放行就通过**
- 批量版 `verify_question_ids_access`(`:276-297`):只取每题的**第一个**题库,逐题校验

如果某题挂载在多个题库下(比如同时挂在"免费章"和"付费章"),批量校验可能因为先取到"付费章"而失败,而单题校验能通过。这是个潜在的不一致,跨题库批量操作时要注意。

### 6.4 题库列表不做权益过滤,前端要靠 403 才能知道哪些要会员

`backend/app/question_bank/api/v1/bank.py:136-158` `get_bank_list` 是**完全公开的接口**,不传 token 也能调通。返回值里**没有任何"是否锁住"的标记**。

前端想做"已锁/可进"的不同视觉,目前**没有简便接口**。需要后端新增一个"批量返回题库 + 当前用户是否能进入"的接口。

### 6.5 决策日志只在 deny 时落库

`access/engine/decide.py:71-96` 的 `DecisionLog` **只在拒绝时写一行**。allow 完全不留痕迹。

如果要做"用户访问审计""会员使用情况分析",需要扩展这里的逻辑或加埋点。

## 7. 常见疑问 Q&A

### Q1: 同事问"我想新增一个题库,默认免费,怎么搞?"

**A**:啥都不用干。创建题库后**不要往 `resource_rule` 里加规则**就是免费。`bank.access_entitlement_code` 留空即可。

### Q2: "我想把某个题库改成需要会员"

**A**:在 `resource_rule` 表里插一条:

```sql
INSERT INTO access_resource_rule
(resource_type, resource_id, entitlement_code, grant_mode, priority, valid_period, status)
VALUES
('qbank', <bank_id>, 'qbank.access', 'access', 100, '[2026-01-01,)', 1);
```

(具体 `entitlement_code` 名要和你们运营/产品商定 —— 一般用通配的 `qbank.access` 让"所有会员通用",或者用 `qbank.access:bank_<id>` 做精细化)

### Q3: "我要给某个用户单独开权益"

**A**:写一行 `direct_grant`:

```sql
INSERT INTO access_direct_grant
(user_id, entitlement_code, valid_period, source, status)
VALUES
(<user_id>, 'qbank.access', '[NOW(), NOW() + INTERVAL ''30 days'')', 'admin', 1);
```

不需要建订阅。`DirectGrantEvaluator` 自动生效。

### Q4: "用户买了套餐为什么显示没权限?"

排查顺序:
1. 查 `subscription` 表:`SELECT * FROM access_subscription WHERE user_id = X AND status='active' AND valid_period @> NOW();`
2. 看 `template_id` 对应的 `subscription_template` 下挂了哪些 pack(`template_pack`)
3. 看 pack 下挂了哪些 entitlement(`pack_item`)
4. 看用户要访问的资源 `resource_rule` 要求的 `entitlement_code` 是什么
5. 比对:第 3 步出来的集合 是否包含 第 4 步的 code

如果都对,但还是拒绝,看 `decision_log` 的拒绝原因(`reason_code`):
- `NO_MATCHING_GRANT` —— 用户确实没有这个 code
- `QUOTA_EXHAUSTED` —— 配额扣完了(trial 模式)
- `RULE_NOT_IN_VALID_PERIOD` —— 规则本身在生效时段外(限免已过/未到)

### Q5: "我要新增一个跨域功能权益(比如'AI 解析')怎么挂?"

**A**:不走资源决策引擎,走 `_user_has_feature` 模式。参考 `verify_filter_access`(`membership_service.py:369-413`):

```python
@classmethod
async def verify_ai_analysis_access(cls, *, db, user_id, ...):
    if not <触发条件>:
        return
    if not await cls._user_has_feature(db=db, user_id=user_id, entitlement_code='qbank.ai_analysis'):
        raise errors.ForbiddenError(msg='AI 解析需要会员权限')
```

然后:
1. 在 `entitlement` 表插一条 `code='qbank.ai_analysis'`
2. 在 `pack_item` 把这个 entitlement 挂到对应的包上
3. 在业务代码的入口调 `verify_ai_analysis_access`

### Q6: "复习错题真的不会校验权益吗?我害怕用户白嫖"

**A**:**真的不校验,这是产品设计**。理由:
- 错题、收藏、笔记都是**用户付费期生成的私有数据**
- 让会员到期用户继续访问自己的数据是合理的(类似 Netflix 取消订阅后还能看离线缓存)
- 用户不能"刷"新题进错题本 —— 因为"刷新题"这一步在 §3 的第 2-4 步已经被拦住了
- 复习类会话不能筛选/不能按知识点限定 —— 只能复习已有的、固定那些题

如果产品决策变了要校验,只需把 `is_review_session` 判断移除即可,但要先权衡用户体验影响。

## 9. 给运维 / 后续 owner 的话

1. **改鉴权前先复盘**:`access_entitlement_code`(题库表)和 `resource_rule`(规则表)目前是**两套并存**的语义,如果你在工单里看到"改题库会员配置",先确认运营要改的是哪一套。
2. **`is_review_session` 是产品决策不是 bug**:有人来报"错题不需要会员是漏洞"时,把本文档第 4 节给他看。
3. **激活码 TODO 是已知缺口**:任何"用户兑换了码但没拿到会员"的反馈,根因都在 `activation_service.py:48`。修这个之前要先和产品确认默认下发哪个 template / pack。
4. **不要在 UserAccount 上加会员字段**:这与"运行时计算"的现行设计冲突。要查会员状态调 `snapshot_service.load`,要持久化下发权益就写 `subscription` 或 `direct_grant`。
