# V2提交、结算与正确率一致性

## 提交确认

- V2练习及评测写接口使用 `CurrentSessionTransactionBeforeResponse`，yield事务依赖限定 `scope='function'`。数据库提交失败时不得发送成功响应。其他业务（支付、鉴权等）原事务依赖不改。
- 客户端一次主动提交生成一个 `submission_key`；重试必须原样复用答案、时长、版本、key。服务端在作答事实的 `grading_result._submission` 中保存键、请求指纹和本次响应版本，先查回执，再检查会话是否结束、版本是否过期。同键不同载荷冲突；已结束/已隐藏的本用户会话也能查询原回执，但不能追加新事实。
- 兼容旧客户端：没有key但有 `save_version` 时，使用版本派生幂等键；两者皆无的提交拒绝，不能用不受保护的请求继续累计次数。旧版本回执返回原版本，不覆盖后来的答案。新客户端始终同时传key和version。
- 正常练习的主动重答是新样本；网络重试不是。考试允许交卷前修改答案，但只有交卷/到时的每题最新事实参与统计，修改过程不叠加样本。未确认的多选/主观题自动保存只写草稿，不计作答样本。

## 原子投影与锁

- 统一锁顺序：用户父行 → 会话/当前响应 → 涉及的题目（ID升序）→ 用户/题目统计及掌握度等投影。同用户不同会话先锁稳定存在的用户行，避免首次创建统计/错题/掌握度行并发唯一键冲突；不同用户同题锁题目父行，避免首次题目统计创建竞争。
- 多题考试/AI批处理在第一次投影前按升序锁全部题目；不能按随机试卷顺序逐个抢锁。
- `grading_result._projection` 的 `submitted`/`graded` 标记和统计、错题、掌握度在同一事务提交。提交投影仅做一次；主观题后续有效判分只补graded维度，不重复加attempt。任一更新失败则整个事务回滚，客户端保留原key重试。
- 旧事实没有标记不能视作漏计。延迟判分兼容旧记录时假定提交基数已统计，不能一律重放历史apply_attempt。旧数据是否实际漏计应先核对，再独立修复。
- 这些保证依赖所有V2写入口走同一锁协议。不要在脚本或其他服务中绕过协调服务直接增量统计。实际数据库死锁/连接中断仍可能导致请求失败，但不应产生半笔提交；客户端以原key重试。

## 考试结算

- 交卷、会话/报告/整卷解析访问到期、隐藏会话和后台到时扫描，都使用会话写锁。首次终态才应用每题最新作答及会话数；重复交卷返回原终态。
- 隐藏进行中会话前先结算，保留终态与事实，只软隐藏历史入口，不把已统计会话改成cancelled。
- Celery任务 `qbank_v2:expire_practice_sessions` 每60秒扫描最多200场，每场独立事务。失败保留未结算状态，下轮可重试；失败日志需监控。必须同时运行worker与beat，新规则未部署/未启动任务时不会自动生效；大批积压需要观测并调整批量/频次。
- 过期考试支持AI补分；不允许给已被最终答案替换的考试中间作答补统计。AI接口使用作答事实ID `latest_attempt_id`，不能把session item ID当作attempt ID。

## 小程序补传与边界

- 提交前先同步写入按用户ID隔离的本地outbox，冻结key/载荷/版本；存储失败必须提示失败。只有服务端确认attempt与version后才删对应队列项。请求失败、响应丢失、版本冲突均保留原数据，不静默换key/改版本重提，不按数量或时间淘汰待同步答案。
- 同一待传题目同答案复用key；不同答案不能覆盖尚未同步的旧答案。先处理旧项，再明确重答。新启动、重新进入会话、网络恢复和前台唤醒可补传；同key进程内single-flight。退出/交卷会等待保存并核对待同步项；页面显示尚未获服务端确认的题数。
- 同题存在待确认提交时，切题等自动保存也只能重试原提交，不得另发草稿PUT推进版本；不同答案拒绝覆盖待同步答案，保留本地编辑并提示先同步原提交。
- 普通练习草稿仍在保存时，确认按钮明确提示“草稿正在保存，请稍后确认作答”，本次确认不被接纳、不锁题也不生成提交key。待草稿成功后再次确认，才按最新版本生成作答；不把已经冻结或发出的提交偷偷改成新版本。
- 账号变化时停止原账号补传、不得用新账号删除旧队列。原账号重新登录可继续。操作系统/用户清理本地存储、卸载、设备丢失，不可能由应用保证恢复尚未到达服务端的数据。对这些情况不宣称绝对零丢失。
- 考试到时后只能确认原来已提交成功的回执，不能把到时前未送达服务端的答案补算进考试。被拒绝的本地答案保留并展示未同步状态；不能为追求补传而放开考试时限。

## 正确率与分布

- `correct_rate` 始终是0到1，分母为已判作答次数，另返回 `graded_count`/`attempt_count`。无已判样本返回null，页面显示“暂无统计”；不是0%。同一用户主动重练计多个样本，不是人数口径。
- `option_select_stats` 将组合分布拆成单选项次数，多选一次选A,C会分别给A/C加1；易错项比例分母为有效作答次数，不是所有选择次数之和。
- JSON分布使用新字典赋值，确保后续增量被ORM识别。提交成功后刷新统计快照；AI成功补分后重新读取服务端当前状态与解析，不沿用提交前缓存。
- 本场结果页显示“已判题正确率”，使用后端 `accuracy_rate`（正确题数/已判题数），不拿整卷题数当分母，不把正确率当得分率。无已判题不展示误导性的0%。

### 点击选择数据详情

- 易错项同一行追加“，全站 N 次作答”，N取 `attempt_count`；不是人数或已判次数。
- 点击“全站正确率”以只读GET `/sessions/{session_key}/items/{session_item_id}/statistics` 获取最新统计，复用解析所有权与考试可见性校验；不触发判题、交卷、奖励或统计累计。
- 弹窗展示题目实际选项（一般为A/B/C/D）的选择次数与次数占比。未选择的选项也展示0次；无作答时占比显示“暂无统计”，多选各项之和允许超过100%。
- 点击“答题时间”使用相同弹窗样式展示 `avg_duration_ms` 与 `duration_sample_count`。平均值实时从在线有效作答事实聚合，仅纳入1000至300000毫秒（含边界），过滤缺失、零用时、明显秒点与超长停留；不修改原始用时、不改旧增量平均字段、不增加表列。
- 平均用时排除外部导入、背题、已删除作答、未结算考试和考试中间答案；正常练习、复习和自适应模式的主动重答分别纳入，已结算且仅隐藏历史入口的会话仍保留样本。考试以最高attempt_no为最终答案，即使最终用时被过滤或最终作答已删除，也不回退采用旧答案。
- 1秒至5分钟是选择题的可解释过滤范围，不是对异常/挂机的完美识别。弹窗展示规则和有效用时样本数；无符合条件的样本返回null，而不是0秒。

## 历史核对（不自动改库）

```powershell
uv run python -m backend.scripts.qbank.audit_practice_statistics --question-id 123 --question-id 456
```

此命令仅SELECT，一次最多100题，对比原始事实与题目计数、组合分布；考试只取最终作答，旧cancelled且无标记的记录列为uncertain，不猜测是否已统计。必须在获得目标环境授权后运行。本轮没有对开发库/生产库执行该命令，也未重建、补写或清零任何历史统计。

本次不增加表/列、不要求DDL迁移；回执和投影标记使用现有作答JSON字段。上线应先后端再小程序，旧客户端至少需要传版本号。不能在已有新作答后直接回滚到不认识回执/锁协议的旧服务实例，否则无法维持幂等保证；滚动部署期间需保证练题写请求由同版本服务处理。
