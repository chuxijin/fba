# 排版文件交付与扫码联调

## 最小交付流程

1. 插件向 `POST /api/v1/render-books/public/exports` 提交排版，取得随机任务凭证。本轮配套后端按认证账号或游客随机标识、完整内容与设置原子复用24小时内的同一任务；更换电脑/手机交付方式不改变内容身份。
2. 内容脚本短请求查询 `GET /exports/{ticket}`，不再让扩展后台等待整个渲染长请求。
3. 服务端复用生成的 PDF / DOCX，将任务及全部分册登记到现有题本表；数据库额度扣减与登记同事务提交。渲染或登记失败回滚，Redis 试看计数另行退回。
4. 新任务的电脑导出逐个提交 Chrome 下载；找回成功结果时先展示文件与二维码，由用户选择再次下载，不自动制造重复文件。浏览器拒绝、无下载记录或立即中断时显示错误，仅重试失败文件，不重新渲染或再次扣额度。“已提交浏览器下载”不等于文件已下载完成，以浏览器下载列表为准。
5. 两种导出方式均展示真实微信小程序码。二维码单独加载，失败可重载，不影响电脑下载，不回退演示图。
6. 微信扫码打开 `pkg/mine/render-books/index`，`scene=rb_{token}`。领取码有效期 24 小时，库中只保存哈希。
7. 已登录插件的题本属于原账号；游客题本由手机登录后首位确认领取的账号保存。领取使用行锁；同账号重复领取幂等，其他账号不能领取。
8. 手机仅定位本次公考题本，不修改全局备考方向；试题、答案分册均可打开，支持 PDF / DOCX。

## 发布前必须核实

- **后端地址**：默认 `pnpm run build` 是本地地址。正式联调需按 `node build.js --api=https://api.yzxj.vip` 构建，并核对实际构建注入的地址及 Chrome 站点权限。
- **更新扩展**：重新加载扩展后刷新题库网页，旧内容脚本不会自动更新。
- **小程序页面**：目标版本必须包含 `pkg/mine/render-books/index`。生产码指向正式版，其他环境指向体验版；体验版需相应微信账号权限。
- **小程序网络**：配置后端 request/downloadFile 合法域名，确认题本列表、领取和文件下载接口已发布。
- **文件存储**：题本文件位于 `RENDER_BOOK_STORAGE_ROOT/public_reformat`，不要在 24 小时领取期内清理。多实例需共享同一存储路径；不是另行上传到微信。
- **运行方式**：本轮使用现有进程内 `BackgroundTasks`，不提供重启续跑。Redis 保存查询状态，最终状态写入失败有三次重试及本进程兜底；兜底不是跨实例持久保证。超时或重启后先检查“我的题本”，避免盲目再次导出。

## 真机验收清单

- 电脑：整卷 PDF、Word、错题双分册均触发下载；到浏览器下载列表核实文件及路径。
- 下载失败：取消/阻止下载后重试，只下载失败的分册，额度和排版任务数不再增加。
- 手机：微信扫描两种导出界面的码，直接进入“我的题本”；未登录时登录回跳仍保留本次领取码。
- 归属：同账号重扫成功；异账号被拒绝；游客题本仅首位确认领取的账号成功。
- 内容：从其他备考领域扫码仍能看到本次题本，返回全部题本后恢复原领域；主册与答案册可打开。
- 异常：到期码给出过期提示，二维码加载失败只重载二维码，不再次排版。
- 重复导出：同账号相同内容连续/并发提交只创建一个新任务、扣一次额度；成功后再次点击找回原文件和二维码；不同账号及不同游客不得共享任务。
- 恢复：状态查询丢包后仅重试GET；确认失败才能明确重试该ticket，重复发送同一次重试不得连续创建新任务；超时、未知、状态丢失不得标为排版失败。

隔离测试不能替代以上微信真机、Chrome 下载及正式配置验收。
