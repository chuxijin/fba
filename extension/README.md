# 公考考场 1:1 标准重排器 (Chrome / Edge 浏览器插件)

一键将粉笔、华图等公考题库网页还原为国考 1:1 标准考场卷（B5道林纸、仿宋四号、1.2倍行距、题目与选项防断联、双面打印自动补白页），支持直接下载到电脑与微信扫码同步手机。

---

## 一、 项目特性

1. **自动网络嗅探**：
   - 注入静默网络拦截钩子（Hook `fetch` / `XHR`），打开粉笔或华图做题页/模考页时，自动无感捕获 130 题完整试卷 JSON；
   - 页面右下角自动浮现古风朱砂印章按钮【考场重排】。
2. **像素级考场排版参数定制**：
   - 自动生成“本部分结束”提示语与强制分页；
   - 紧凑排版节约纸张（允许断行跨页）可调；
   - 手动双面打印支持（奇数页自动补白页）；
   - 反向设问陷阱词加粗（如错误、不属于、不符合）；
   - 仿真考场封面（含准考证填涂区、注意事项警示语）；
   - 资料分析与数学运算分数放大（Office MathML 矢量渲染）；
   - 仿宋/宋体/黑体/楷体、小四/五号/四号、1.0~1.5倍行距自由调节并带实时预览。
3. **两用交付分支**：
   - **💻 下载到电脑**：一键生成并在浏览器原生触发高清 PDF / Word 下载；
   - **📱 导出到手机**：弹出专属小程序码，微信扫一扫自动沉淀在用户小程序【我的题本】中，随时查阅或调用合作打印下单。

## 二、 如何在浏览器中加载安装（开发与测试）

1. **构建扩展产物**：
   ```bash
   cd D:\100_Work\101_Program\Proj\fba\extension
   pnpm run build
   ```
   构建产物将输出在 `extension/dist` 文件夹下。

2. **在 Chrome / Edge 浏览器中安装**：
   - 打开浏览器，进入扩展管理页面：
     - Chrome: 地址栏输入 `chrome://extensions/`
     - Edge: 地址栏输入 `edge://extensions/`
   - 在页面右上角打开 **“开发者模式”**（Developer mode）开关；
   - 点击左上角的 **“加载已解压的扩展程序”**（Load unpacked）按钮；
   - 在弹出的文件选择器中，选中本项目的输出目录：
     `D:\100_Work\101_Program\Proj\fba\extension\dist`
   - 此时浏览器扩展栏中将出现 **【公考考场重排器】** 图标。

3. **进入真题网页体验**：
   - 打开粉笔网页版（`https://www.fenbi.com`）进入任一套模考或真题练习；
   - 页面右下角会自动出现圆形的 **【考场重排】** 悬浮按钮；
   - 点击即可呼出米黄色考场排版设置卡片，选择导出到电脑或微信扫码导出到手机。

## 三、 架构设计与工程规范

为维护代码的高可维护性，避免跨层打补丁与逻辑耦合，开发前请务必阅读：
👉 **[架构设计与开发规范文档 (ARCHITECTURE.md)](./ARCHITECTURE.md)**

- **分层规范**：
  1. `interceptor.ts`（Main World）：纯净网络嗅探管道，只转发原始 JSON，严禁掺杂业务逻辑；
  2. `content/index.ts`（Isolated World）：路由与调度中心，按域名分发流量；
  3. `adapters/<platform>/`：平台专属适配器，所有题库异构处理 100% 封闭于此；
  4. `content/ui/`：表现层，只认标准 `UnifiedPaper` 与 `q.is_wrong`。
- **KISS 原则**：恪守极简设计，避免过度工程化。

## 四、账户与登录同步

### 代码职责

- `auth-protocol.ts`：官网、content script、后台共用的地址、类型、消息校验、JWT 有效期与超时工具；纯逻辑，无网络和存储依赖。
- `auth.ts`：凭据/账户缓存、认证 HTTP 请求、后台消息调用；`auth-bridge.ts` 负责官网会话校验、退出与首次恢复。
- `account-state.ts`：Popup 和排版模态框共用状态；`content/site-auth.ts` 只负责顶层官网的消息转发。
- `auth-diagnostics.ts`：按需检查接口与浏览器实际站点权限；报告不含凭据和个人资料。

### 状态约定

- 缓存仅优化昵称/头像展示，额度与权限以服务端为准。缓存绑定 Token 摘要及服务端，用户最多复用 24 小时且不超过 Token 有效期，游客最多 5 分钟。
- 登录、退出、额度变更通过 storage 同步，旧请求不能覆盖新账号。可见视图每 60 秒及获得焦点时核对；断网保留已确认身份并提供重试，不补造额度。
- 官网会话优先从已打开的顶层页面读取，缺少桥接时自动补注入；无官网标签页则读取 `/api/extension/session`。来源及会话有效性均需校验。
- 退出先清本地再撤销服务端，阻止旧凭据自动恢复；已撤销会话重复退出视为成功。凭据过期后重新登录，当前不自动续期。

### 本地验收与排查

官网为 `http://localhost:3000` / `http://127.0.0.1:3000`，后端为 `http://127.0.0.1:8000`。统一配置在 `auth-protocol.ts`，生产域名尚未接入。

运行 `pnpm test`、`pnpm run build`，在 `edge://extensions/` 重新加载 `extension/dist`，并刷新已有做题页面。验收顺序：官网登录 → Popup 同一用户 → 另一个官网地址自动登录 → 扩展退出同步官网 → 官网重新登录恢复扩展 → 官网退出同步其他标签页。断网时确认缓存与重试表现。

仍显示游客时展开 **登录同步检查**；**从官网同步** 可恢复已打开页面的桥接，**复制检查结果** 用于反馈。

| 检查结果 | 处理 |
| --- | --- |
| `Blocked` | 在当前官网的 🧩 菜单开启网站总开关“允许在此网站使用扩展”，再刷新；单个扩展已授权不代表网站总开关已开启 |
| 桥接未连接/版本过旧、旧退出标记 | 保持已登录官网打开，点击“从官网同步”；旧标记只在会话校验成功后解除 |
| 官网脚本未握手、错误端口 | 刷新更新后的官网，使用上列 3000 端口地址 |
| 连接失败/超时 | 检查服务与浏览器代理；官网会话接口不可用时可通过已打开页面同步，后端仍需可用 |

开源参考：[Sentry Cookie Sync](https://github.com/getsentry/cookie-sync) 使用 Cookie API 同步选定会话；本站使用官网桥接共享经后端校验的 JWT。
