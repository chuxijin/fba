# 错题导入与练习记录的用时关联

## 数据口径

- 题干、选项等内容用于复用题目；用时属于某次作答，不是题目属性。
- “导入错题”不虚构整卷或练习会话。能核验当前粉笔报告与原站题号时，保存该次真实错误的独立 `capture.external_wrong` 快照；没有可靠报告身份时仍只保存旧式错题快照，不用标题或导入批次猜测一次新作答。
- “导入记录”保存原站逐题作答及 `duration_seconds`，后端转换为作答事实的 `duration_ms`。
- 错题详情的答案和用时取自同一条最近错误作答。缺失用时保留 `null`，真实零秒保留 `0`，不借用更早一次的用时，也不按整卷用时均摊。

## 整卷归档与错题的关系

- 整卷按“账号 + 来源平台 + 本次练习报告编号（`source_key`）”去重；重复导入同一报告只补全缺失信息，不再新建整卷记录。
- 完整导入同一次练习后，再导入其中的错题，会复用题目及可关联的真实作答，不再生成第二份整卷记录；两种导入顺序均支持。
- 单独导入错题不会自动生成整卷，因此不能认为所有错题都已包含在某份已归档的练习记录里。导入记录也不等于自动把其中所有错误题加入错题本。
- 同一张卷重新做一次属于另一份练习，应按新的报告编号另行归档，不能按试卷标题合并。
- 整卷摘要、逐题快照、作答事实和错题状态各有用途，分表保存并不等于重复导入；历史重复题仅做安全关联，不物理合并。

## 两个入口的统一规则

题干和选项共用 `normalizeImportStem` / `normalizeImportOptions`，同时统一行内符号、图片布局、选项前缀与多选答案编码。前缀处理不能吞掉 `Answer`、`AB`、`A+B`、`A + B` 等真实内容。

粉笔错题额外保留 `entry_metadata.source_question_key`，取自原始题目标识，不能用页面题序替代。此字段与记录导入的 `source_question_key` 对齐，即使原站 `id` 和 `globalId` 不同也能保留可靠身份。

## 旧数据兼容

### 跨试卷的错题与导入批次

- 同一道题已经在错题本时，复用题目及当前错题状态，不重复建题，不抹除首次来源、复盘和记忆历史；不同真实报告中再次做错时，另存一次错误，累计错误次数增加，最近错误答案及日期取真实作答。
- 每次批量导入用 `capture` 录入事件保存“本批次—错题”的关联及本次卷名、章节。原错题的首次来源和原批次不被覆盖；录入事件不算复盘，也不虚构作答。
- 成功数包含新增及成功关联的已有题。例如第一季29道错题、其中11道已存在，应显示“已导入29题，新增18道，已有11道”，本批次可查看全部29道。已有题不算失败、跳过或缺答案。
- 分片共用批次标识；同一批次同一错题的关联幂等。全部是已有题的批次仍可查看；批次分页按实际录入时间排序。
- 撤销只解除当前批次关联。仅本批次新建且未被其他批次使用的错题可移除；已有或共享错题及原复盘保留。题目仍被作答、练习投递、题库编排或独立错误事件引用时，题目及材料均不得清理。独立错误事件不是批次归属，不随批次撤销而删除。
- 历史批次仍从首次来源元数据兼容读取。不根据卷名猜测或自动给历史批次补题；配套后端发布后，可重新导入原卷，建立完整的新批次关联。此前第一季的18道历史批次不会仅因更新插件就自动变成29道。

### 旧题目身份

旧指纹未命中时，导入和错题详情可按稳定来源身份查找候选题，且必须同时满足：

1. 同一用户所有的私有题，相关来源记录未删除。写入复用仍只选择有效题；历史只读关联允许原题已被软删除，不恢复旧题、不迁移作答到新题 ID。
2. 同一平台、同一原站题号；旧版仅支持从外部键解析正整数题号，不按 `o1` 等题序猜测。
3. 题型、内容格式与规范化题干、选项一致。

兼容读取不会合并或删除历史题目，不修改历史作答、复盘状态或排期。若不能可靠证明是同题，则仍显示未知，不模糊匹配。新旧客户端只有展示差异时允许补全缺失用时，但保留原快照；真实内容、答案或已有用时冲突仍拒绝覆盖。

## 公共匹配逻辑

- `CRUDExternalPractice.find_import_question` 统一两个导入入口的“内容指纹优先，可靠来源兜底”顺序；指纹命中或没有可靠来源身份时，不额外查询旧来源。
- `WrongReviewService._get_external_source_peers` 统一错题详情与复盘关联使用的历史同题查询；调用方继续限定导入来源，身份缺失时不查询。
- 新错误事件使用已有表，不新增表或迁移。写入沿用用户锁、状态锁及分片单题 savepoint；保持用户隔离，不删除必要的历史快照。

## 每次真实错误与报告幂等

- 身份使用“账号 + 同一稳定题的原站平台/题号 + 真实报告编号”，不使用试卷标题或导入批次。一张卷重做会有不同报告编号；换批次重导同一报告不能重复记错。同报告里不同原站题号的错误也分别保留。
- 插件仅从当前 URL 所属的已捕获报告读取逐题错误答案与用时。答案、用时和报告编号来自同一条作答；缓存属于其他报告、题号不可靠或没有真实答案时，不附加新错误事实。
- `wrong_occurrence` 保存真实报告编号、当次用时和真实日期；未知日期/用时为 `null`，真实零秒为 `0`。独立错误事件的采集时间与未知作答时间分开，不把导入时间伪装成作答时间。
- 先导入错题或先导入整卷均支持。整卷已归档的真实错误与独立快照按同报告同题关联；仅同报告同答案可补缺失用时，已知答案或用时冲突拒绝覆盖。不同报告中最新错误用时未知时，绝不借旧报告用时填充。
- 整卷导入只同步已在错题本的题，不自动将整卷所有错误题加入错题本。重读未变化的原报告也可补旧漏关联；重复同步不重复增加次数。
- 旧错题的初始计数仅抵扣一次。优先按原报告编号匹配；没有原编号时，只有作答在错题创建前已归档、同题同答案同卷且候选唯一，才兼容抵扣原初始次数。不能可靠定位的旧错误不伪造报告身份，历史数据核对/修复需另行明确授权。
- 旧版仅保存在状态中的首次错选，在更新最新答案前另存 `legacy_initial` 快照，保留旧答案和首次来源；真实日期和用时未知时仍为 `null`，不能拿最新作答补给旧快照。没有保存过的旧答案也不从新报告反推。初始快照排在真实报告错误之后，采集日期不当作真实提交日期。
- 后续匹配到可靠的真实原报告时，初始快照由该报告替代展示和计数，不双记；没有原报告编号时仍需唯一的严格历史证据。批次撤销不删除独立错误或初始快照，重建状态后找回旧错误只计一次。
- 重导较早报告不会把最近错误回退。能确认真实作答在已解决时间之后的再次错误会重新激活，复盘次数和记忆数据不清零；历史旧错误或日期未知不据导入时间重置已解决状态。

## 发布边界

此修复涉及插件和后端，需要发布配套版本才在线上生效；仅替换插件无法改变旧后端的关联行为。当前已有的 1.0.6 ZIP 不包含本轮“每次错误记录”修改，需要另行构建新版本，不能认为旧包会随源码更新。

后端上线后，第一季已保存的原作答用时可通过严格历史关联读出，无需改写生产原题/作答；累计错误事件在重导错题或原报告时幂等同步。本地修复和内存测试不等于已部署、已修复生产数据或已通过微信/浏览器验收。

回归覆盖插件入口一致性、两种导入顺序、旧重复题读取、账号与软删除隔离、缺失与零秒用时。后端测试仅使用内存 SQLite 和 mocks，不连接真实数据库。
