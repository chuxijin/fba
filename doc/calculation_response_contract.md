# 计算练习统一作答协议

## 范围

保留基础计算、资料分析填空、资料分析实战、进阶计算四个出题入口和现有批次外层结构。
每道题新增必有的 `contract`，协议版本为 `1.0`，与出题算法的 `generator_version` 独立。
旧字段暂时兼容专用公式组件和旧客户端，不再作为新版小程序的判题入口。
本次不引入 SDK，不改动其他能力训练模块。

## 三种作答结构

- `numeric`：一个或多个数值输入项；假设分配用 `base`、`growth` 两项，其余单项为 `answer`。
- `singleChoice`：统一 `{id, display}` 选项，`correctOptionId` 指向正确选项；A/B/C/D 仅为页面序号，不是判题 ID。
- `comparison`：`expected` 为 `greater`、`less`、`equal`，严格判定。

统一展示入口为 `contract.display`，包括 `material`、`prompt`、`expression`、`mode`。
复杂公式图仍使用现有专用组件和旧展示字段，不能将所有图形展示强行压成纯文本。

数值示例：

```json
{
  "version": "1.0",
  "display": {"material": "", "prompt": "求增长率", "expression": "", "mode": "text"},
  "response": {
    "kind": "numeric",
    "fields": [{"id": "answer", "label": "答案", "value": 13.1, "display": "13.1", "unit": "percent", "rule": "relative", "tolerance": 0.05}]
  }
}
```

## 判题约定

- 只读 `value` 判题，`display` 仅供展示；真值在后端统一计算，不在页面重复推导。
- `relative`：绝对误差不超过真值绝对值的 5%；真值为零时仅零通过。
- `exact`：严格相等，容差为零；保留基础精确计算、前两位等题型原有规则。
- 多输入项必须全部通过；选项和大小比较不使用数值容差。
- `percent` 中 13.1 表示 13.1%，不是 0.131；`percentagePoint` 表示百分点。客户端不隐式换算单位。
- 选项 ID 在单道题内稳定，重排时应连同 ID 一起移动，不应重新编号 ID。
- 协议包含练习参考答案，适用于当前自测练习；不是防作弊考试协议。正式考试应另做服务端判题，不下发答案。

## 发布及验收

先部署后端，再更新小程序。新版客户端遇到缺少或不合法的 `contract` 会明确报错，不回退到旧公式计算。
本次只修改本地代码，没有部署生产服务。

真机重点检查：基础精确/估算题、资料分析数值/比较题、实战单选、进阶六种实际题型的公式和题干模式，特别是假设分配双输入和百分数输入。
核对错题参考答案、选项高亮、重试、末题结束及历史记录展示。
