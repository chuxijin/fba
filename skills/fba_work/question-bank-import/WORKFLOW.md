# 题库数字化与入库发布：AI 独立交接规范

更新：2026-11-01。本文是本功能唯一现行规范。新会话先读仓库与 `skills/fba_work/AGENTS.md`、本文件和本轮 README；历史记录用于定位，不能替代实时核验或操作授权。

## 1. 范围与授权

将用户有权使用的 PDF、扫描图或 Word 题库转换为结构化成果，经打样、内容审核和质量检查后，发布到**本轮明确指定的环境**。

- 开始先确认题库名称、源文件、实际题数/题型、章节、解析模式、目标环境及合集/分类。缺失就问，不照抄旧任务 ID。
- 只要求提取、检查或归档时，不联网、不连接数据库、不导入。开发与生产分别授权，不默认必须双环境，更不因 dev 成功就自动写 prod。
- 正式写库、改答案/默认解析、恢复生产均须明确授权；DDL、迁移、事件竞态与事务方案由主控处理，不下放机械工作代理。
- 题目已在库中、只需手写精简解析或切换默认时，转 `../question-explanation/WORKFLOW.md`；考研兔/云易学接口采集分别走其对应规范，不混用导入器与数据契约。
- 凭据只取自当前受控配置，禁止把连接串、密码、Cookie、签名写入文档、脚本或日志。旧版本文档曾包含明文凭据，已移除；这不等于凭据已轮换，用户应通过正式流程评估更换。

## 2. 每轮目录与恢复

使用 `runs/YYYYMMDD-任务名/`，不在仓库根或 scratch 新增任务产物：

```text
README.md              # 范围、授权、真实状态、异常、下一步、精确ID
source_info.json       # 源文件路径/哈希、页数、题号/页码映射、章节清单
source/                # 必要源文件或不可重建的OCR/校正结果（受控保存）
final/                 # 最终Excel、预览及其版本/哈希
qc_report.json         # 离线结构检查，不能替代内容审核
import_result.json     # 每个授权环境的返回结果/精确ID/提交证据
verify.json            # 独立核验、题目映射、备份位置与恢复说明
scripts/               # 仅本轮可复现工具，历史写库脚本禁止重放
work/                  # 可重建的分片、图片、日志、调试预览
```

通用工具在功能 `scripts/`。任务创建器拒绝路径穿越和覆盖；例：

```powershell
uv run python skills/fba_work/question-bank-import/scripts/new_bank_run.py 20261102-example --name '本轮确认名称' --code qb_example
```

状态按事实记录：待调研/打样待审/制作中/待授权导入/部分失败待核对/指定环境已提交待复核/已复核。未发现执行证据时标待核实，不补写“已完成”。
恢复会话先核对已有源/成品哈希和数据库实时状态；文件或脚本存在不代表执行过，超时也不等于回滚。

## 3. 源文件调研与渐进制作

1. 检查源文件可读性、页数、文本层、目录、题号范围和答案分布，记录实际题量，不用书名“720/300”推断。
2. 先做一题，再做一章/一套，覆盖单选、多选、跨页、图片公式、长解析等边界，获用户确认后才全量。
3. 按源文件还原章节；两级是当前选择题模板的约定，不强迫所有书只有两级。若原书需一级/三级、材料或主观题，先确认新契约，不能塞入10列模板造成丢失。
4. OCR 须逐项对照原页，保留低置信度与人工校正记录。唯一OCR结果不是可随意删除的缓存；外部OCR涉及数据外发与费用时先确认授权。
5. 题号必须用章节+题型+原题号等稳定来源键定位；题号重置、跳号、重印、跨页须显式处理并报告，不能凭全书单调递增计数吞掉异常。

## 4. 解析三种模式

| 模式 | 来源 | 规则 |
|---|---|---|
| A 原生详析 | 原书有完整文字解析 | 忠实保留实质内容，清理版式和页眉页脚；发现与答案冲突先标疑，不擅自圆答案。 |
| B 选项旁批注 | 选项附考点/错因，另有详析 | 答题选项与批注分离，保留坐标/来源映射。第二解析是否创建、版本名与默认策略须另行确认，不擅自合并或覆盖。 |
| C 原书仅答案 | 无文字解析 | 先说明缺失；仅在用户要求后逐题撰写，依据配套资料/权威知识核对，标明为新增解析，不冒充原书。脚本只搬运/校验，不能机械生成知识解释。 |

解析 HTML 应经过项目支持的安全清洗，不含脚本/事件/危险链接，预览对题干及选项文本转义。精编解析采用 question-explanation 的格式；原书详析不被强行套成同一模板。

## 5. 提取防错要求（按实际版面实现，不套万能正则）

- 分题结合题号、字体/坐标、页面区域与答案映射；章节/题型重置时重新建状态，缺号或倒序必须告警，不能自动忽略。
- 选项标号需有版式边界，避免把 AIGC、3D 打印中的 C/D 当选项。行内并列选项也要支持；不是简单规定“只能行首”或“任何题都只有ABCD”。当前模板仅支持ABCD选择题，其他格式停下扩展。
- 单选末题与多选标题分区处理；按原页定位标题边界，不用不带范围约束的正则删正文。标题词出现在真实题文时人工判别，禁止盲删。
- 所有字符串检查非法控制字符，保留合法换行/制表符；不得为保存成功而静默截断超长单元格。Excel字符串有长度上限，超限须报告并另定存储契约。
- 完整核对原题号/答案/章节/选项数，重复项和疑似截断列入异常清单。结构零错误不等于内容零错误。

## 6. 当前10列成果契约与门禁

本模板**仅用于两级章节、ABCD四选项的单选/多选**；不要宣称它覆盖所有公考/考研题型。第一张工作表（不是任意活动表）为题目数据，表头顺序如下：

```text
section_l1, section_l2, question_type, stem,
option_A, option_B, option_C, option_D, answer, explanation_default
```

- 题型：单选/单选题或多选/多选题；单选答案1个A—D，多选2—4个不重复字母，按A—D顺序规范输出。
- 章节、题干、四选项、答案、解析均必填；缺解析的中间稿不得作为发布成品通过。
- 此表不含 score/item_key/多解析/材料字段；不要直接当作其他导入器模板。若需这些字段，升级契约及质检后再用项目导入服务。
- 服务会为未给分值的题默认设分，须在本轮确认是否接受；不能默认“多选必定2分”。

门禁按 AGENTS 的规则通过后台 cmdc 执行，主控接收最终结论与失败摘要；cmdc不可用时说明后按允许的例外处理。其执行命令为：

```powershell
uv run python skills/fba_work/question-bank-import/scripts/qc_validator.py <本轮最终Excel> --expected-count <核实题量> --output <本轮qc_report.json>
```

必须零结构问题、题量一致；表头错误、空表、公式单元格、非法字符、答案重复/越界、空解析等均阻断。报告保留全部异常，不能只保存前50个。
还须独立核对章节与题号覆盖、答案源映射、跨页内容、图片/公式、全文标题残留和人工打样结论；脚本不能证明无语义错位。全景HTML仅是辅助审阅，不是自动验收。

## 7. 导入服务与环境检查

优先项目现行 API/`ImportTaskService.import_bank`，执行前重读当前实现与调用方事务约定。此规范不授权改生产后端实现。

- dev查询工具 `fba_dev`，prod查询工具 **`fba_prob`**，生产主机用 SSH MCP。不在本文固定连接串、用户、分类或合集 ID。
- 每个环境分别核对服务器、数据库、schema/search_path、操作者权限、分类及合集；dev/prod ID 不保证一致。名称、版次、bank_kind 由本轮确认，不强制所有工作都叫“【27版】”或分类8。
- bank 无 name/kind，名称和类型在 bank_revision；question 无 bank_id，需经 bank_item 与 revision 关联。
- 导入前备份相关范围并核对 bank code 冲突、稳定来源键、重复题、同名不同父级章节、分类/知识体系唯一性与分值。

2026-11-01静态核对当前服务发现的行为（未来使用前重新核实）：

1. `import_bank` **内部调用 db.commit()**。不能在外层 begin 后 rollback 就声称只读预演；预演使用隔离环境或经审核的不提交实现，不能执行正式导入当测试。
2. 校验不合格行可能被剔除，其他有效行仍发布；必须先让全量离线校验通过，并要求返回 `fail_count=0`、`success_count=预期数`。
3. bank code 冲突时自动换编码，不是幂等或断点续传；运行前查冲突，失败/超时后查实时结果，禁止盲重跑。
4. 当前章节缓存按层级+名称，非完整父路径；同层同名不同父级可能误合并。这类输入先暂停并评估服务修正，不能只凭质检通过就导入。
5. 首个非空 explanation_* 被设默认；本轮只用 explanation_default 时是原始默认，不等于后续精编模式。新题 content_hash 当前可能为空，不假定可按hash跨环境唯一映射。

服务参数以当前签名为准：db/user_id/file_content/bank_name/bank_code/bank_kind/collection_id/category_ids/primary_category_id/description，含知识点时还需 knowledge_system_id；均来源于本轮确认，不提供固定ID的可直接执行生产模板。

## 8. 提交与独立核验

只导入已授权环境，保留输入哈希、精确返回值、实际提交证据和操作者；两环境是两次独立提交，不存在天然跨库原子事务。
完成后独立查询并保存：

1. bank/current_revision_id、名称/类型、published状态与真实条目数、独立题数、总分相符。
2. 章节层级/父路径/题量与源目录相符，零题章节是否创建按事先约定。
3. 每题题干、选项、答案、解析完整，每题恰有一个有效默认，题号与来源映射可追溯。
4. 合集挂载、分类与主分类正确，知识点/材料按本轮契约正确关联。
5. 既有题库、用户练习与解析没有越界修改；所有失败/跳过项有明确解释。

双环境核对按稳定来源键和内容，不能假定ID相等；仅有开发/生产脚本而无结果证据时，状态标“历史记载，待核实”。本次归档不访问数据库，不补写实时验证结论。

## 9. 异常修复与清理

暂停写入，先查实时状态并保留快照。修复要限定环境、bank/revision、精确题目ID、解析版本及软删除范围，备份旧值，加入旧内容断言/并发保护，在事务中处理并独立复核。不按题干模糊度或code前缀批量覆盖所有解析，不擅改答案。跨环境分别核对范围，不能自动将生产修复复制到未授权开发库。

与数据库对应的最终Excel/预览更新时保留修订记录与输入哈希。源文件、唯一OCR/人工校正、最终成果、执行结果、ID映射、备份与验证证据长期保留；源数据如在外部位置，确认可访问且哈希一致后再认定可重建。
完成且可追溯后仅清理已被最终文件覆盖的work分片/日志/重复预览。历史固定参数脚本放run/scripts或archive并标禁止重放，不以归档名义执行它们。
