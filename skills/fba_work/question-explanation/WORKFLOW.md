## 1. 给新 AI 的任务说明

你要帮助用户逐题手写精简解析，并安全写入指定环境的题库解析表。

1. 先定位题目范围，读取题干、完整选项、标准答案、原解析和现有解析版本。

4. 原官方解析必须保留；不修改题干、选项、答案、错题状态或学习记录。

## 5. 撰写 HTML 规范

允许标签仅 `p`、`b`、`span`、`br`。不得使用 `<s>`、外层卡片、脚本或事件属性。
**content_html 内禁止 ASCII 双引号；所有 HTML 属性用单引号。引用用中文引号。**

固定结构：

```html
<p><b>【题型】</b>选非题（选错误项）</p>
<p><b>【考点精析】</b></p>
<p>A <span style='color:#008A00;font-weight:bold'>✓</span> 激光交会对接雷达利用激光方向性好、测量精度高的特性进行测距定位｜利用激光的方向性与测距精度。</p>
<p>B <span style='color:#008A00;font-weight:bold'>✓</span> 天舟九号对接时的姿态调整利用了牛顿第三定律——力的作用是相互的｜推进器喷出工质，获得反向作用力。</p>
<p>C <span style='color:#DA291C;font-weight:bold'>✗</span> 飞船与地面测控站利用微波进行通信，微波频率<span style='color:#DA291C;text-decoration:line-through;font-weight:bold'>高于</span><span style='color:#0066CC;font-weight:bold'>低于</span>可见光｜微波比可见光频率低、波长长。</p>
<p>D <span style='color:#008A00;font-weight:bold'>✓</span> 导航系统依托北斗卫星导航系统，利用电磁波接收卫星信号实现定位｜电磁波可在真空中传播。</p>
<p>本题选错误项，故选 C。</p>
<p><b style='color:#008A00'>【答案】C</b></p>
```

### 5.1 按真实题型判断，不只看数据库 single_choice

- **选是题**：A-D逐项，答案项绿✓，其余红✗。不符题意不一定是事实错误，要写清“与题意不符”，不要强行划掉正确常识。
- **选非题**：标题 `选非题（选错误项）`；错误答案项红✗，其余绿✓，**不能把被选择项一律标成绿✓**。结尾写“本题选错误项，故选 X。”。
- **多选题**：标题 `多选题（选正确项组合）`；A-D逐项，所有答案项绿✓、其余红✗；末尾答案如 `ABD`。
- **组合题**：标题 `组合选择题（选正确项）`；逐条①②③④标✓/✗，不要把A-D组合当成判断句；结尾“正确的为①②④，对应 B，故选 B。”。
- **计数题**：标题 `计数题（数正确项）`；逐条①②③④判断，结尾“正确的为①②④，共 3 项，故选 C。”；核对C选项确实为3。
- 如问“有几项错误”或“错误组合”，明确选择目标并相应统计，不能硬套“正确的为”。

### 5.2 政治理论、常识判断：原文保留与精简纠错

- **原文保真优先于简短。**政治理论、常识判断的解析必须完整复现原选项，字母、选项顺序、文字、数字、标点、限定词与原题一致，不概括、缩写、换词或调整语序。“精简”仅指追加的解析理由，不是压缩原选项。
- 正确项：`字母 + 绿✓ + 完整原选项｜简短依据`。错误项：保留完整原句，只给原句实际错误的最小词句加红色删除线，并在紧邻位置追加蓝色正确表述；原错词仍然可见，不用纠正后的句子整体取代原选项。
- 原选项与追加纠正/解释须可区分。删除线中的文字必须来自该项原文，不得自行改写一句“错误说法”再划掉；没有明确事实错误、只是与题意不符的，保留原文加排除理由，不硬造替换词。
- 组合题/计数题对题干中的①②③④等原陈述也逐字保留，不能用知识点摘要替代。A—D的原组合/数量选项仍保持原样，最终结论核对其对应关系。
- 答题选项`question.option_data`始终不改；红删蓝增只发生在解析展示中，亦不改题干或答案。HTML转义和必要标签包装不算改写，但不能丢失原字词、标点或图片公式；若现有标签白名单无法无损展示图片/公式，先暂停确认展示方案，不默默剥图或猜写。
- 追加理由通常1—2句，保留决定判断的知识点，不堆砌原解析整段、讲话全文或重复背景；原选项较长也不得因此删减。
- 明确事实错误：仅划掉错误词句，紧跟蓝色正确内容。颜色固定：绿`#008A00`、红`#DA291C`、蓝`#0066CC`。
- 普通知识题的错误/排除项应有删除线改正，或 `｜` 后给出排除理由（兼容旧模考校验器）；逻辑填空按第5.3节逐词括号批注（一词一行），不套此规则。
- 正确项不能只写“正确/符合题意”，应说明知识依据。
- 内容依原解析但不盲从；若答案与论证冲突、数据错位或来源明显存疑，记录并暂停该题，不静默改题或强行圆答案。
- 图片公式不得简单剥离后猜内容；要读取原图核对。例如第41季104096选项D图片实际为40°—60°。
- 不添加未经核验的具体日期、法条号、引语或政策出处。法律和时效性事实有疑问时查权威来源。

2026-11-01补充：历史精简解析有概括改写原选项的做法，不满足以上“逐字复现”要求；不能把旧格式通过当作已通过原文一致性检查。用户本轮不要求追溯重写或再次发布，保留原成品/提交证据，此规则用于后续任务；若将来重做需另定范围和授权。

### 5.3 逻辑填空：选项旁批注式简便解析

**2026-11-01用户纠正：必须逐空、逐词批注，不是给整组选项统一打勾叉；2026-11-02再纠正：每个词单独一行，不再在同一行用“／”把多词连起来。**本节标题保留以兼容旧链接，现行样式名为“一词一行批注版”，覆盖此前整组选项后接`｜`、逐词“／”同行连接两种旧样式。

#### 内容结构

1. 保留`【题型】逻辑填空（选词填空）`、`【考点精析】`、结尾“故选 X。”和`【答案】X`。
2. A—D各一段，字母后不加整组选项的✓/✗。每个原词**紧接自己的括号**：`词语（✓：本空为何可用）`或`词语（✗：本空为何不合适）`；**每个词单独一行（HTML同一段内以`<br>`分隔）**，选项字母只出现在该选项首词行，续行不再重复字母。
3. 成语、实词、虚词全部逐词标注，不漏任何空。理由只谈紧邻的这个词及对应空位，不把整组分析放到最后一个词的括号里。
4. **✓表示这个词在这一空可用或可先保留，不等于整组选项正确。**错误选项中也可以有绿✓，不能因为整组不选就把每个词都标✗。正确组必须全部核实，不能只验证一个空。
5. 行数等于空数：单空一行、双空两行、三空三行，每词一行且顺序与原选项一致。每词理由通常半句至一句，约6—20字，必要限定不截断；不堆词典释义或重复长文段分析。
6. 可先用一句话指出关键语境。默认不添加重复总结、长背景，不对原词加删除线或替换成答案词。

#### 判断与内容审核

- 每个词独立代入对应空位，核对词义、对象、词性、程度、感情色彩及上下文逻辑；已找到某空排除整组后，**仍需核实其他词**，不能顺手全部标错。
- 括号里写具体语境差异，不泛写“不合适”“语义不符”。弱对比写“不如……贴合”“可先保留”，不夸成绝对搭配禁忌。
- 红✗表示该词不适用于本空，不表示成语本身错误。绿✓既可出现在正确组，也可出现在被其他空淘汰的组；不能再使用“恰好一个绿✓”的整组校验规则。
- 以原解析为参考但不盲从。未分析过的其他空不能自动补✓；遇到无法可靠判断的词或答案冲突，记为待核实并暂停该题，不为排齐符号硬编理由。
- 若有多个整组都能全部判✓，须继续比较全句与上下文并核对答案，不能为迁就标准答案给其中一个词强行标✗。

#### 双空示意（第41季104101，仅用于说明布局）

> A 浩浩荡荡（✓：可形容时代浪潮的声势）  
> 　交口称赞（✗：此处宜用被称赞的表达，原句搭配不顺）  
> C 瞬息万变（✓：对应时代变化）  
> 　风靡一时（✓：对应专业曾经热门）

字母只写在每个选项的首词行，续行不再出现字母。A第一空可以保留，不代表整组可选；C两词均需各自核实。HTML仅给括号中的符号上色，不整行标红：

```html
<p>A 浩浩荡荡（<span style='color:#008A00;font-weight:bold'>✓</span>：可形容时代浪潮的声势）<br>交口称赞（<span style='color:#DA291C;font-weight:bold'>✗</span>：此处宜用被称赞的表达，原句搭配不顺）</p>
```

标签仍仅允许p/b/span/br、属性单引号，content_html不含ASCII双引号。绿`#008A00`、红`#DA291C`；一词一行用`<br>`换行（Markdown预览用换行），选项原文和括号理由均须正确转义。

#### 展示位置与执行边界

- 此布局只在**解析里复现的选项**中使用，不修改`question.option_data`、题干、答案或答题前展示。真正改答题页交互须另行授权。
- 首轮先做3—5道真实题打样，覆盖不同空数；不足则全部，用户确认后再扩展或发布。规范本身不授权写库或补做历史季次。
- 本轮JSON可记录`analysis_style=word_inline`与每空`word/symbol/reason`，脚本仅负责转义、渲染及校验，不能生成词义判断或新增数据库字段。
- 校验须按词而非整组选项计数：每项符号/括号数等于空数，且一词一行（`<br>`分隔、字母仅首词行、无“／”残留）；去除批注后原词序与源相同；所选组全部✓，其他组至少有一处可靠✗。这只是结构一致性检查，逐词可用性仍由人工审核。

逻辑填空可另记 `analysis_style=word_inline` 与源子题型、定位依据和逐词判断，写在本轮JSON/README，不凭空新增数据库字段或改表。
输入中的数据库题型另存于 source，不要因为输出“计数题”就修改数据库 single_choice。
源快照包含旧的 is_default、content、answer_data、option_data 等，便于检测用户在撰写期间做的修改。

若中断：先读 README → 实时查生产版本 → 对照 source/final → 只处理缺失或明确未提交的范围。
**SQL文件存在不等于已经提交；看到旧日志也不能代替实时查询。**

## 7. 安全执行流程

1. **定位**：环境、用户、完整来源/当前revision、科目、独立题数、现有解析版本分布。
2. **快照**：导出完整题目与原解析；生产查询走只读工具。
3. **质量检查**：缺选项/空答案/越界答案/题干截断/标题串入/选项错位/重复ID/图片公式。
4. **手写**：逐题完成。用户授权或 AGENTS 指示允许时可分片子代理并行；每个代理只写自己的文件，不授予生产写库任务。
5. **校验**：按当前 AGENTS 将测试/门禁委派给其指定的后台执行工具（当前为agy），仅接收最终结论与失败摘要；指定工具不可用时记录异常，再按AGENTS允许的例外处理。历史cmdc记录不作为新任务的执行指令。
6. **备份**：修改任何旧解析之前，备份目标题目的原解析完整行到独立生产备份表；使用唯一任务名称，不删除历史备份。
7. **生成事务SQL**：ON_ERROR_STOP，源数据指纹与旧内容/默认状态断言，必要行锁，目标范围断言，写入后断言。
8. **dry-run**：使用 `-v commit=0`，必须以ROLLBACK结束且所有断言通过。失败时不得继续提交。
9. **提交**：同一文件 `-v commit=1`，检查真实退出状态与COMMIT，不用 `tail` 等管道掩盖psql失败。
10. **独立复核**：MCP重新查默认数、版本数、内容格式、答案、旧内容保留、目标题目覆盖和无越界修改。
11. **归档**：更新README和verify记录；仅清理本任务自己创建的远端临时文件，保留生产备份表和本地成品。一次性分片、调试日志、预览统一写入本轮`work/`；确认完成且不影响追溯后可清理。遵循本功能README中的保留规则。

### 7.1 校验清单

- 总条数、独立question_id、输入输出顺序和集合完全一致。
- 政治/常识原文一致性：仅去除新增的蓝色纠正、追加理由与展示标记，保留删除线包裹的原错词，还原后逐项与源选项比对；组合/计数原陈述同样核对。检查文字、数字、标点及顺序，不以“意思相同”代替一致。图片/公式核对原资源，不直接剥除；存在未确认的展示差异就暂停。旧校验器没有此检查时，不能声称已满足。
- answer与源一致；末尾【答案】和“故选”一致。
- 含【题型】【考点精析】【答案】，无ASCII双引号，HTML标签正确闭合、无额外属性。
- 通常每选项或判断句恰好一个✓/✗；逻辑填空逐词版除外，每个词一个符号、每词独立一行，颜色语义正确。
- 选非绿色集合为选项全集减答案，普通选是/多选绿色集合为答案；逻辑填空逐词版不能套这个整组规则。
- 计数/组合结论与绿色序号集合一致，并与实际答案选项对应。
- 逻辑填空：字母/词语/原词序与源一致，**每词单独一行（内部`<br>`分隔），选项字母仅首词行**；每个词后恰一个`（✓/✗：理由）`，每项括号及符号数等于空数；正确组全✓，其他组至少一✗，允许错误组的可用词为✓。无整组前置符号，无“／”同行连接，无末尾统一`｜`理由，不要求对原词加删除线。
- 逻辑填空内容复核：每一个词均独立核实，✓不代表整组正确，理由有语境依据且无伪造绝对搭配禁忌；题干/option_data/答案未变。结构检查不能代替人工判断。
- 结构校验不能代替人工内容复核，特别是法条、时效性政策、选非和数量。

### 7.2 写库注意

- 模考通常旧official为默认。可先将其设为非默认再插入新default，均在同一事务；不改official.content。
- 默认切换是高风险事务逻辑，主控负责，不下放给批量撰写代理。
- 已有人工default时应停止并核对，不用盲目upsert覆盖。重复执行应中止或识别已完成状态。
- 不能仅凭唯一索引保证每题只有一条is_default=true；这是不同约束，必须另查默认唯一性。
- 可使用base64载荷避免SQL引号转义损坏，SQL文件UTF-8与LF。
- 导出JSON建议 `SELECT json_agg(...)::text` + psql `-At -o`；**不要直接COPY TEXT格式输出JSON**，反斜杠会被二次转义。
- dev→prod仅在确实需要跨环境时使用content_hash唯一映射；不能按两边ID相同假定匹配。
